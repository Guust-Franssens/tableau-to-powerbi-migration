# `t2p` unified CLI — implementation architecture

✅ **Review contract.** Invariant: faithful delegation to existing authorities; a façade never masks a non-zero child result or presents its own inference as a gate verdict. A false PASS is fail-open and blocks merge; a false refusal is fail-closed (stops operator progress) and is a defect to triage, but never justify weakening a gate. Closed surface: **N = 209 existing literal script-command references** across five cohorts (personas 35, skills 28, docs 62, CI 9, tests 75; 40 distinct target paths), excluding this note’s own examples. Independent oracle: invoke the same script and arguments directly, then compare exit code, stdout/stderr and authoritative output artifacts to `t2p`. If review discovers a new risk class, simplify/descope before adding another guard.

## 2. Entrypoints and façade

✅ **Recommend `python scripts/t2p.py` first**, also callable as `uv run python scripts/t2p.py`; do not add `[project.scripts]` in the first slice. The repo requires Python ≥3.11, calls itself a script toolkit with no importable library, sets `py-modules = []`, and currently has no console entrypoint (`pyproject.toml:1-7,49-50`). This avoids package discovery/install changes and works from a checked-out or copied toolkit with its local interpreter. A packaged `t2p` shim instead requires an installed project/venv and PATH setup; a stale installed shim can target a different checkout. Reconsider packaging only after the repo has an explicit package layout and install/upgrade contract.

⚠️ `t2p.py` should resolve `REPO_ROOT = Path(__file__).resolve().parents[1]` and execute absolute script paths with `sys.executable`; never resolve from CWD or accept a second engine path. Python puts the script directory on `sys.path`; use only the CLI’s own sibling registry imports. Do not import command modules: the front door itself mutates `sys.path` and imports helper modules (`scripts/start_migration.py:27-33`), while command modules own `argparse`, `SystemExit`, and mutable globals. Existing engine resolution derives from the installed plugin and deliberately raises rather than falling back (`scripts/engine_source.py:43,100-113`).

⚠️ Use a **thin subprocess façade**, not in-process imports: pass an argv list, `shell=False`, `cwd=REPO_ROOT`, and the selected Python executable, with `-B` for children such as `run_status.py` whose contract forbids bytecode writes; stream inherited stdout/stderr and return the child’s exact exit status. This preserves argparse/exit behavior, isolates crashes and import side effects, and keeps the script as the behavior owner. A command may graduate to import only after it exposes a documented side-effect-free callable, has direct API tests, and the façade-vs-script oracle proves argument/output/exit equivalence; no first-slice promotion.

⚠️ Windows recommendation: pass the same argument vector (never a shell command string), with paths as individual args; quote only when rendering a copyable command. `uv run python scripts/t2p.py` uses the project environment; `python scripts/t2p.py` needs the caller’s Python/dependencies. Neither creates a `t2p.exe` PATH launcher.

## 3. Registry, help, and stable output

⚠️ Single source of truth: new `scripts/t2p_registry.py`, with each exposed command declaring `name`, `script`, `tier`, `stability` (`stable|preview|deprecated`), help summary, and output mode. A registry is routing metadata only—no gate/readiness rules. The root help is generated from registry metadata; `t2p <command> --help` delegates `--help` to the mapped script’s argparse, avoiding a second option parser. CI checks every mapped target exists, unique names/targets are intentional, help invokes successfully, and generated command summaries match the short pointers in `scripts/README.md`. Keep `scripts/README.md` as the full file inventory; make it point to generated CLI help rather than re-copying option manuals. Existing `sync_agent_conventions.py --check` and `check_navigation_index.py` show local drift-gate patterns (`AGENTS.md:5-20,25-26`; `.github/workflows/checks.yml:83-90`).

⚠️ `status` delegates read-only observations to `run_status.py`; `paths` combines run metadata (`work_dirs.py`), the measured path report (`check_path_ceiling.py --json`), and a non-authoritative git visibility observation. `next` invokes the applicable authority—`check_reference_readiness.py`, `check_unit.py`, or `credential_gate.py list`—and names its result/code and owner; it may suggest the next registered command but may not issue its own PASS. Existing `run_status.py` explicitly says exit 0 is diagnostics, not readiness, and performs no repair/process/network operation (`scripts/run_status.py:1-7`; `scripts/README.md:77`).

⚠️ JSON v1 envelope: `schema_version: "t2p/v1"`, `command`, `status` (`ok|findings|cannot_establish|error|interrupted`), `exit_code`, `authority` (gate/script or null), `native_exit_code` (null before child start), `data` (the unchanged existing JSON value, if the script has one), and `artifacts` (paths/receipt references, not copied migration state). Add optional fields compatibly; incompatible changes get a new schema version. Treat unknown/new child fields as opaque best-effort data. Reuse `run.json`, existing `--json` reports, `engine-output-receipt.json`, and deployment journals; no new state database, stage ledger, or competing receipt.

⚠️ Human mode inherits live child stdout/stderr. In `--json`, stdout contains only the one envelope; progress/diagnostics go to stderr, while a declared child JSON result is preserved under `data` (or artifact path/hash references point to its existing output file). Registry output mode distinguishes JSON stdout from human logs; do not parse arbitrary prose as evidence. Launch Python with `-u` / `PYTHONUNBUFFERED=1`, do not buffer a running child, and keep non-TTY output plain and complete. Existing `start_migration.py` already uses unbuffered children, flushes progress, and reports 15-second heartbeats (`scripts/start_migration.py:34,317-349,503-506`). Full-refresh progress remains conditional on trace events; preserve its current heartbeat/silence warning and timeout rather than claiming row counts always exist (`AGENTS.md:362-379`).

## 4. Privacy, exits, interruption, and paths

⚠️ Required façade privacy invariant: never echo PAT secrets, session tokens, `.env` values, customer server names, or raw argv in command echoes, JSON envelopes, or exception text. Existing redaction helpers are `tableau_env.redact`, `env_redactor`, and `redacted_note` (`scripts/tableau_env.py:333,422-442`); use existing `host_paths` checks for host-location disclosure. Do not assume PAT redaction removes customer hostnames. Preserve required local run paths in local output, but do not publish them into committed artifacts or PR text.

⚠️ Public exit composition: wrapper-owned usage errors exit **64** before spawning; launch failure exits 70; after spawn, return the child code unchanged (including non-zero); never replace a child failure with a later “success.” `native_exit_code` and `authority` make meanings explicit.

| Source | Native code | Facade behavior |
|---|---|---|
| Facade syntax | 64 | Return 64 before spawning; do not confuse with child argparse exit 2. |
| Child cannot launch | 70 (proposed) | Report typed launch failure; no child code exists. |
| Child / delegated gate | Exact native code | Pass through unchanged; record authority and native code. |
| Tableau oracle | 0 all captured; 1 partial non-credential failure; 2 Tableau credential needed; 3 total non-credential failure; 4 no views selected; 5 required reference render absent | Preserve all codes and manifest; meanings are script-specific (`scripts/capture_tableau_oracle.py:2000-2007`). |
| `run_estate.py` DoD | 3 | Preserve refusal; never treat as oracle code 3 or successful bundle (`docs/operator-runbook.md:1244`; `scripts/README.md:76`). |
| `preflight.ps1` | Native 0/1 in its normal final branch | Pass through, including critical-missing 1 (`scripts/preflight.ps1:945-952`). |
| Interrupt | 130 (proposed) | Cancel/reap invocation-owned child work and retain partial evidence. |

⚠️ This is a routing table, not a new global interpretation of child codes: every code is paired with its authority, and other native gate values pass through untouched.

⚠️ Recommended: interrupt only invocation-owned work. Mirror the proven front-door pattern: Windows `CREATE_NEW_PROCESS_GROUP` + `CTRL_BREAK_EVENT`; POSIX a new session/process group; bounded wait then reap, return 130, and retain partial evidence (`scripts/start_migration.py:297-342,685-686`). Test actual descendants; process groups alone do not prove every grandchild is gone. Never sweep Power BI Desktop by process name: cleanup is PID-scoped and `scripts/check_desktop_orphans.py` owns leak detection (`AGENTS.md:574`).

✅ `paths` and `status` must show recorded run path/runs-parent and actual physical path; repo-local vs external root; git visibility/commit-safety; longest current file and directory and remaining budgets against **259 UTF-16 file / 247 directory units**; and pre-engine projection as pass/over/unknown (unknown until evidence exists). When over, print the exact new-run command including original scope selectors and `--runs-parent <short-root>`; preserve the old run as evidence, never relocate it. `start` prints the physical path first and last; `status`/`next` repeat it. If a measured same-user `subst` alias is active, show it beside the recorded path as temporary/non-authoritative; never persist it in `run.json` (`#734` comment; `docs/windows-path-limits.md:3-20,319-359`; `scripts/check_path_ceiling.py:212-213,428-472`). Keep quoting/long-path failures visible; no path-ceiling bypass.

## 5. Commands, hard boundaries, and compatibility

⚠️ Proposed core routes: `doctor` → plain `preflight.ps1`; `start` → `start_migration.py` for a live site (local single input remains `parse_tableau.py`, folder `run_estate.py`); `status` → `run_status.py`; `paths` → `work_dirs.py` + `check_path_ceiling.py`; `next` → named readiness/credential gates; `unit prepare` → `package_unit.py`; `validate` → `check_reference_readiness.py` / `check_unit.py`; `credentials list|reprobe` → `credential_gate.py list` / `reprobe_blocked.py`; `deploy --dry-run` → `deploy_estate.py --dry-run`, then `verify_bindings.py` after deployment. `doctor` never upgrades tools mid-migration; the one session-start `-Update -CheckUpstream` timing rule remains unchanged (`AGENTS.md:30-39`).

(3) Do not weaken any gate, version floor, or engine single-source rule (`scripts/engine_source.py:23-31,100-113`). (4) Python-first; no new PowerShell scripts.
